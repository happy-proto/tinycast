# 开发与交付

修改前读取项目 `AGENTS.md` 以及任务涉及的开发、架构、功能和测试文档。

1. 确认 checkout 在 `main`，读取工作区和 `origin/main` 状态，保留用户已有改动。
2. 直接在 `main` 实现需求，完成项目 Definition of Done 和与风险匹配的专项验证。
3. 用户授权提交后，按修改目的建立明确的 commit；不要把 i18n、行为修复和工具改动混成一个提交。
   对同一需求的实现、测试和文档可以一起提交，不为凑“一功能一提交”改写既有历史。
4. 用户授权推送后，推送 `main` 并独立回读远端 SHA 与 CI 状态。普通开发不需要强推。
5. 需要本地安装验收时，读取 [dev-app.md](dev-app.md)，从干净的 `main` 安装完整 Dev App。

区分源码检查、测试、构建、安装、进程启动和可见行为验收。构建成功不代表已安装，安装成功
不代表当前窗口来自新实例；必须验证进程路径和实例数量。
