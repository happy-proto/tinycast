# 开发与交付

修改前读取项目 `AGENTS.md` 以及任务涉及的开发、架构、功能和测试文档。
读取 [改造记录](../../../../docs/fork-changes/README.md) 定位目的和同步边界；修改原有改造时更新
原记录；记录只说明当前行为、入口、验证和上游同步风险。

1. 确认 checkout 在 `main`，读取工作区和 `origin/main` 状态，保留用户已有改动。
2. 直接在 `main` 实现需求，完成项目 Definition of Done 和与风险匹配的专项验证。
3. 在用户授权范围内，一个独立改造维护一个完整 commit，实现、测试和记录一起交付。
   对已有改造的修正归入其 commit，不累计中间修正或基线推进提交；不同改造不合并成一笔。
4. 普通开发在用户授权推送后推送 `main`；同步上游默认按 [upstream-sync.md](upstream-sync.md)
   完成覆盖推送，无需额外确认。推送后独立回读远端 SHA 与 CI 状态。
5. 需要本地安装验收时，读取 [dev-app.md](dev-app.md)，从干净的 `main` 安装完整 Dev App。

区分源码检查、测试、构建、安装、进程启动和可见行为验收。构建成功不代表已安装，安装成功
不代表当前窗口来自新实例；必须验证进程路径和实例数量。
